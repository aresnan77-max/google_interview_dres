## Technical Blog Strategy

### Platform Options
| Platform | Pros | Cons |
|----------|------|------|
| dev.to | Built-in audience, SEO | Less customizable |
| Medium | Professional feel, distribution | Paywall issues |
| Hashnode | Custom domain, developer-focused | Smaller audience |
| Personal Site | Full control, shows initiative | Need to build + maintain |

### Content Calendar (First 3 Months)
| Week | Topic Type | Example |
|------|-----------|---------|
| 1 | Tutorial | "Getting Started with Unity ECS" |
| 3 | Deep Dive | "Understanding Unity's Rendering Pipeline" |
| 5 | Opinion | "5 Mistakes I Made Learning Game Dev" |
| 7 | Tutorial | "Building a Multiplayer Game with Netcode" |
| 9 | Case Study | "How I Optimized My Game from 30fps to 60fps" |
| 11 | Guide | "Complete Guide to ScriptableObjects in Unity" |

### Writing Tips for DevRel
- Start with the problem, not the solution
- Include a working GitHub repo for every tutorial
- Show mistakes and debugging process (developers relate to struggles)
- End with actionable next steps
- Cross-post to multiple platforms for reach

## Conference Talk Preparation

### Talk Formats
| Format | Duration | Content |
|--------|----------|---------|
| Lightning Talk | 5-10 min | One key insight with a demo |
| Standard Talk | 25-40 min | Deep technical topic with examples |
| Workshop | 60-120 min | Hands-on coding with attendees |

### Building Your First Talk
1. **Start local**: Meetups, company tech talks, university events
2. **Record everything**: Post to YouTube for portfolio
3. **CFP strategy**: Apply to 10+ conferences per quarter
4. **Topic selection**: Your unique intersection (Unity + Cloud + DevRel)

### Talk Structure Template
```
Hook            (2 min)  — Story or demo that grabs attention
Problem         (3 min)  — Why this matters to the audience
Solution        (15 min) — Technical deep-dive with live code
Demo            (5 min)  — Working example
Key Takeaways   (3 min)  — 3 bullet points the audience remembers
Q&A             (5 min)  — Prepare 3 common questions + answers
```

## Open-Source Contribution Strategy

### High-Impact Contributions for DRE Candidates
1. **Documentation PRs** — Fix typos, improve examples, add tutorials
2. **Sample projects** — Create official-quality samples for SDKs
3. **Bug fixes** — Find and fix issues in popular game dev libraries
4. **Tool creation** — Build developer tools (linters, generators, templates)

### Target Projects
- Unity packages (com.unity.*)
- Google SDKs (Firebase Unity, Play Games Plugin)
- Popular open-source game frameworks (Godot, MonoGame)
- Developer tools (Rider plugins, VS Code extensions)

### Contribution Workflow
1. Star and watch target repos
2. Read contributor guidelines
3. Start with "good first issue" labels
4. Engage in discussions before big PRs
5. Follow up and iterate on review feedback
